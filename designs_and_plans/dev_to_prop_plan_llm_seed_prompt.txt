Stage 5 — Adapt the PDF Pipeline
This is the biggest implementation stage.
Why it is different
Your PDF parser doesn't simply upload files.
It
reads a PDF -> creates dozens of images -> creates folders -> verifies output -> counts files -> deletes old pages
This is much more than a normal upload.
New workflow
Instead of
PDF -> Filesystem -> Render -> Filesystem
it becomes
PDF -> Temporary Local File -> Renderer -> Temporary Images -> Storage Backend -> Cleanup
The parser still uses local temporary files because libraries like PyMuPDF, OpenCV, and MoviePy are designed around local file access. The difference is that the source PDF is downloaded from storage first, and the generated page images are uploaded back through the storage interface.
Code affected
Mostly the PDF utilities.
